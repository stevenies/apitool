REST API Generator

What is a REST API?

REST APIs are web-based Application Programming Interfaces (APIs) providing clients with an easy means to access and update data sourced by a data provider. A key characteristic of REST APIs is that they expose business data resources (aka business data objects) that can be created, read, updated, and/or deleted by the API. When developing a REST API an important first step is to create a business domain model identifying the data resources, resource attributes, and relationships between resources. The business domain model is the main design artifact defining the API's interface between the data provider and its clients from a business perspective.

What does the REST API Generator tool do?

The REST API Generator provides two important capabilities to greatly reduce API development effort. First it transforms a business domain model expressed as a UML class diagram into an API interface specification documented using the OpenAPI standard. An OpenAPI specification is a machine-readable document describing the API's endpoints, request and response formats, and other API details needed by clients to know how to call the API.

Second the REST API Generator processes an API's OpenAPI specification to generate code implemementing the API's skeleton infrastructure. The skeleton implementation is a fully functional API that can receive requests from the client and return default responses but contains stubs for the business logic. The API skeleton code provides API developers with an initial "quick start" code base, thus significantly reducing the time and effort required to develop a REST API.

In short by using the REST API Generator development activities that used to take weeks to perform manually can now be accomplished automatically in a matter of minutes. Instead of developers spending time to manually create API specifications and write API boilerplate code they can now focus on implementing the API's business logic to more quickly realize the API's business value proposition.

What are the steps to create a new REST API?

Developing a REST API employs a standard software development lifecycle as shown in the following diagram. The ideation phase identifies the business need for the API and defines the API's business value proposition.
A key artifact produced during this phase is the API's business domain model identifying the API's data resources transferred over the API. The second phase, API Design, develops the API's client interface specification defining the API's callable endpoints and request/response formats. The API interface specification is then used to generate the API's skeleton implementation code resulting in an operational API but containing stubs for the business logic. Finally the third phase, API Implementation, replaces the endpoint stubs with the API's business logic to complete the API's implementation. The following paragraphs explain the steps performed during each phase in more detail.

Step - Create the business domain model

Use the StarUML modeling tool to create a UML class diagram representing the API's business domain model. The business domain model should identify the data resources to be transferred over the API, the resource attributes, and relationships between resources. Once the business domain model has been created save it to your local computer using StarUML's native .mdj file format.

Step - Generate the API's OpenAPI interface specification

Open the API Spec Generator tool, upload the StarUML .mdj file containing the API's business domain model, and then press the Generate API button. In response the tool will generate the API's specification document defining the API's client interface.

Step - Tailor the API's specification to remove unwanted endpoints

The API Generator tool generates an OpenAPI specification document defining standard sets of CRUD (Create, Read, Update, Delete) callable endpoints for each data resource. Once the specification has been generated it can then be tailored to remove unwanted endpoints. For example, if the business domain model does not require resource deletion capaibilities then the DELETE endpoints can be removed from the API specification.

Step - Generate the API's skeleton implementation

After the API's specification has been tailored it can be used to generate code comprising the API's skeleton implementation. The skeleton implementation is a fully functional API that can receive requests from the client and return default responses. It fully implements the API's controller and model boilerplate logic while providing API endpoint stubs that can be extended to include the API's business logic.

To generate the API's skeleton code open the API Code Generator tool, and then press the Implement API button. In response the tool generates code comprising the API's model objects, controller endpoints for processing client requests, and service components containing stubbed endpoints for the business logic.

Step - Implement the API's business logic

Once the API's skeleton implementation is generated it is then ready to be used as a starting point for API developers to implement the business logic. The skeleton implementation provides a quick-start code base that significantly reduces the time and effort required to develop a REST API.
