Suppose the business goal is to build an API enabling clients to view the available insurance plans and to select one or more in which to enroll.

The first step is to create an OpenAPI specification defining the API's client contract. The OpenAPI documentation standard is an open-source, vendor-neutral specification for describing REST APIs. It enables both humans and machines to understand and interact with APIs without needing to see the underlying implementation code. The OpenAPI specification consists of detailed JSON code specifying the API's endpoints, operations, parameters, and data formats. As such it is a foundational tool for designing APIs using a "design-first" approach, ensuring consistency and facilitating integration.

Traditional Costs for API Specification Development

How long will it take a proficient API developer to manually write the specification's JSON code? The API spec for the above example has a nominal number of API endpoints, request/response data payloads, and schema definitions. Even so the API's spec contains 14000 lines of detailed JSON code. For an API of this size experience has shown that a developer typically needs three to four weeks to manually write the JSON code, test it, and resolve issues. Assuming that the developer can finish the JSON code in three weeks at an average developer rate of $60 per hour, the cost to manually write the client API specification is $7,200!
